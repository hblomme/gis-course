8.3.5 Using geometric properties

What is a geometry?

On the previous pages you learned how to query features by their attribute values. Here we show how to query their geometry.

Before we start, it is important to define clearly what we mean by a geometry in GIS. A geometry describes the location and shape of a feature. It consists of a geometry type ((multi-)point, line or polygon) on the one hand and coordinates on the other: one pair of coordinates for a point, several pairs for a line or polygon.

A multi-geometry consists of several separate parts. A country with islands for example can be represented as one feature with a multipolygon geometry: one polygon for the mainland and one for each island. All parts of a multi-geometry have the same geometry type.

In an expression you can calculate various properties of a geometry, such as its area, length or number of parts.

Building blocks

To work with geometries in an expression, QGIS provides the following elements:

  • the variable @geometry, which retrieves the geometry of the current feature
  • $area, $length and $perimeter: three geometry functions written with a $ sign that calculate common geometric properties of the current feature without requiring any additional input
  • a wide range of other functions: ready-made commands that perform specific tasks. These functions require input, called arguments, which you provide between brackets after the function name. For example, distance(geometry1, geometry2) calculates the minimum distance between two geometries.

Below we discuss each of these in turn.

1. The variable @geometry

@geometry retrieves the geometry of the current feature. It works in a similar way to a field name between double quotation marks: a field name retrieves the attribute value of each feature, while @geometry retrieves its geometry.

In QGIS the @ sign identifies variables. You can find @geometry in the list of Variables (B) in the expression editor.

2. $area, $length and $perimeter

  • $area: the area of a polygon
  • $length: the length of a line
  • $perimeter: the perimeter of a polygon

These are functions, but special ones. They start with a $ sign and, unlike other functions, they need no input: they always work on the current feature. That is why they are written without brackets.

You can find them in the central list of the expression editor (B), under Geometry. As always, you can find more information about each of them in the panel on the right (C).

These functions take the Earth’s curvature into account by using the reference ellipsoid defined in the project properties (Project ▸ Properties… ▸ General). They also return their result in the units set there (by default square metres and metres), even when the layer uses a geographic CRS such as WGS 84, where coordinates are expressed in degrees.

The expression shown above, $area > 300000000000, filters all states with an area larger than 300 000 000 000 m² (300 000 km²). For each feature, QGIS calculates its area using the reference ellipsoid and checks whether it exceeds this threshold. Only five states pass this filter: Alaska, Texas, California, Montana and New Mexico.

3. Other functions

QGIS offers a wide range of functions to query geometries, to check how they relate to each other in space, or even to create new geometries on the fly. All these functions work in the same way: you write the function name and give the input it needs as arguments between brackets. If there are several arguments, you separate them with commas, as in function_name(argument_1, argument_2). You find these functions in the central list (B), under Geometry. Most of them expect one or more geometries as arguments. In the examples below, words in italics such as geometry1 or number1 are placeholders: you replace them with actual values, such as a geometry or a number. Some examples:

  • distance(geometry1, geometry2): calculates the minimum distance between two geometries.
  • crosses(geometry1, geometry2): checks whether two geometries cross each other. It returns 1 if they do and 0 if they do not.
  • make_point(number1, number2), make_line(point1, point2), make_polygon(line): create a new point from a pair of coordinates, a line from two or more points or a polygon from a closed line.
  • x(geometry), y(geometry): return the x or y coordinate of a point, or of the centroid (the geometric centre) of a line or polygon.
  • x_max(geometry), x_min(geometry), y_max(geometry), y_min(geometry): return the largest or smallest x or y coordinate of a geometry. In a geographic CRS such as WGS 84, x is the longitude and y the latitude, both expressed in degrees. In a projected CRS such as Belgian Lambert 72, x and y are distances in metres to the east and north of a fixed origin.
  • area(geometry), length(geometry), perimeter(geometry): calculate the area, length or perimeter of a geometry.

These are only a few examples. QGIS has many more geometric functions, and their possibilities are very interesting. So do not limit yourself to these: browse the group Geometry (B) and read the documentation (C) of the functions you come across.

Syntax and arguments

Functions differ in the input they need, and it is important to get this right. Some functions need one argument, others several. The type of argument and the order in which they must be provided also vary. For example, some functions expect a geometry followed by a number, while others require only a text string. You do not need to memorise all this information. You can always find what you need in the documentation (C).

Documentation

For each function the documentation shows what it does (C1), its syntax (C2), the required type of each argument (C3) and examples showing how to use it and what output to expect (C4).

Three examples:

centroid() needs one argument, a geometry, and returns a point geometry that is the middle of the input geometry.

Other functions require several arguments, separated by commas. These arguments are not necessarily geometries. For example, make_point() requires two numbers: the x-coordinate and the y-coordinate.

distance() requires two geometries and returns a number representing the minimum distance between them. For a polygon, this is the distance to its nearest edge. Between two points, it is simply the distance from one point to the other.

Nesting

The output of one function can be used as input for another. This is called nesting: one function is placed inside another. We will illustrate this with an example.

Suppose you have a layer containing the Belgian municipalities. You want to filter only those municipalities that meet both of the following conditions:

  • their area is larger than 100 km²
  • the centre of the municipality is less than 100 km from the city centre of Ghent

For the first condition you need to calculate the area of each municipality and compare it with 100 km². For the second you need to calculate the centroid of each municipality and measure the distance from that point to the centre of Ghent. Unit of measurement

When you use geometric functions, it is of course crucial that you know which unit you are working with and how exactly the calculations are done. In practice, this differs from function to function. The documentation (C) tells you for each function which unit it uses.

Some functions seem to do the same thing. You may have noticed above that we gave both $area and area() as examples to calculate the area of a feature. Still, these variants can give different results, because the calculation is done differently.

A concrete example shows the difference:

  • area(@geometry) calculates the area with the coordinates of the geometry, in the CRS of the layer. For Belgium in a layer in WGS 84 (in degrees) this gives about 3.90: square degrees, a number that means little.
  • $area calculates the area with the measurement settings of the project, on the ellipsoid. For Belgium this gives about 30 664 km².

In a projected CRS in metres the two give almost the same result. For Belgium in Lambert 72 area(@geometry) gives about 30 662 km² and $area about 30 664 km²: a difference of about 0.01%. That small difference comes from the distortion of the projection (see Projection distortions in chapter 5). The exact numbers depend on the layer you use.

Here is a short overview of the differences:

$area, $length, $perimeter area(@geometry), length(@geometry), perimeter(@geometry)
Calculation method Uses the project ellipsoid by default. If none is set, calculations are planimetric. Always planimetric, using the CRS of the geometry.
Units Uses the measurement units set in the project properties. Uses the units of the geometry’s CRS (e.g. m² for a projected CRS in metres, or degrees² for WGS 84).
Suitable for Ellipsoidal calculations are suitable for measuring areas and distances over large regions. They also work well for smaller regions. Suitable for calculations over relatively small areas, provided the CRS introduces little distortion.
To avoid large deviations Choose an appropriate ellipsoid in the project properties. Use a suitable projected CRS with limited distortion in the region concerned.

If you calculate areas with area(), use a CRS with an equal-area projection, such as ETRS89-extended / LAEA Europe (EPSG:3035) for Europe. Such a projection keeps areas correct (see Equal-area projections in chapter 5).
