9.7 Labelling and styling with expressions

In the previous sections you learned how expressions can be used for calculations and queries. However, they can also be used to control how features are displayed on the map, for example through labelling and styling. You can compose the text of a label with an expression, and, as with queries, you can define conditions and apply a particular label or style to the features that meet them.

Compose the label text

So far, we always labelled a layer based on a single field. However, you can also compose the label text with an expression. When you open the Labels tab in the Layer Properties, you will notice that next to the drop-down list where you select the attribute field (Value), there is also a button . Click it to open the Expression Builder. Here you can compose an expression that returns a value (usually a text), which is then used as the label of each feature. Take for example a layer of US cities with a field for the name of each city (NAME) and a field with the abbreviation of the state it lies in (STATE_ABBR). If you want to label each city with its name followed by the state between brackets, such as Chicago (IL), you can use the expression concat("NAME", ' (', "STATE_ABBR", ')'), which you already saw in Text and math functions.

Rules

In the example above all features of the layer are labelled in the same way, just as in chapter 4. They all use the same field or expression to determine the label text, and the same label style is applied to all of them. Of course you have also learned how to use Categorized or Graduated symbology to vary the appearance of features, but these approaches assign each feature exactly one symbol, based on the value of a single field.

However, sometimes you want more control over how individual features are displayed. For example you may want to label only the largest cities and vary the font size according to their population. Or you may want to combine several conditions to determine the symbol used for a feature.

Rule-based styling makes this possible: it allows you to create rules in which you define a condition and link it to a specific style. QGIS then applies that style to all features that meet the condition.

Rules work in the same way for labels and for symbology. Below we first explain how you create them. Then two examples show a complete map, one for labels and one for symbology.

Rule-based labeling and symbology

In the layer’s Layer Properties, open the Symbology tab and select Rule-based at the top (A1). For labels, you open the Labels tab and select Rule-based Labeling in the same place.

The large empty area (A2) is the rule overview. It is initially empty because no rules have been defined. Click the green plus symbol at the bottom of the window (A3) to create a new rule. This opens the Edit Rule window.

Rule editor

The rule editor has two main sections below the Label field (where you can enter a descriptive name for the rule, B1):

  • the condition that identifies the features to which the rule applies (B2)
  • the style that determines how these features are displayed (B3)

Condition (B2)

The condition goes in the Filter field and takes the form of an expression. Expressions can be typed directly into this field or entered through the full Expression Builder, opened with the button (B4). The expression must return either TRUE or FALSE. Typical examples include comparisons or functions such as crosses(). As in the previous sections, QGIS evaluates the expression for each feature and applies the rule to those for which it returns TRUE.

Instead of a condition, you can also choose Else (Catch-all for other features, just below the Filter field). Such a rule applies to all features that match none of the other rules. Without an Else rule, those features get no label or symbol.

Style (B3)

In this section you determine the symbol (marker, colour, size…) or the label style (label text, font, colour…) that the features meeting the condition receive. It looks and works exactly like the settings of Single Symbol symbology and Single Labels respectively.

Click OK to save the rule. All the rules you created are shown in the rule overview (A2). To edit a rule, double-click it. You can delete a rule with the red minus symbol (A3).

Features that meet several rules

When using rule-based symbology, a feature that matches several rules gets the symbol defined by each of them. QGIS draws these symbols on top of each other, in the order of the rule list. This means that the last rule in the list is drawn on top. If a symbol covers the symbols below it, those are no longer visible.

Examples

Labelling the largest cities

Consider a point layer containing the major cities of the United States. The aim is to label only the most populated cities, with the label size reflecting their population. We therefore need three rules, one for each group of cities to be labelled:

  • Rule 1
    • condition: "POPULATION" > 2000000
    • label text: concat("NAME", ' (', round("POPULATION" / 1000000, 1), ' M)')
    • style: 20 pt, black
  • Rule 2
    • condition: "POPULATION" > 1000000 AND "POPULATION" <= 2000000
    • label text: NAME
    • style: 14 pt, dark grey
  • Rule 3
    • condition: "POPULATION" > 500000 AND "POPULATION" <= 1000000
    • label text: NAME
    • style: 9 pt, grey

For the first rule, the label text is an expression instead of the field NAME (see Compose the label text), so that these cities also show their population in millions, for example New York (8.8 M). In the next two rules we use the <= operator to include cities with exactly 2 000 000 or 1 000 000 inhabitants respectively. Cities with fewer than 500 000 inhabitants match none of the rules, so they remain unlabelled.

When you have created the rules and click OK at the bottom of the Layer Properties, you immediately see the result in your map canvas: only the largest cities are labelled, and the larger the city, the larger its label.

Seats in the House of Representatives

Above, each rule used a simple condition on one attribute value. Just as in other expressions, you can also combine several fields in a rule and use functions, such as the aggregate functions mean(), maximum() and minimum().

Consider a polygon layer containing the US states, with the number of seats in the House of Representatives (REPR1990, REPR2010) and the population (POP1990, POP2010) of every state. The map should show three aspects of representation:

  1. Change in seats: did the state gain seats between 1990 and 2010, lose seats, or keep the same number? Each outcome gets its own fill colour.
  2. Change in relative representation: did the number of seats per inhabitant increase or decrease between 1990 and 2010, relative to the average state? States where it increased are hatched.
  3. Extremes in 2010: which state had the most seats per inhabitant, and which had the fewest? These two states get a coloured outline.

Note that with these criteria a state can meet several conditions. Every state that is hatched or outlined, for example, also has a fill colour. A classification based on a single attribute, such as Categorized symbology, is not well suited to this task, because it gives every feature exactly one symbol. With rule-based symbology every characteristic gets its own rule.

We build this map in two parts: first the fill colours, then the hatching and the outlines.

Fill colours

In the Symbology tab, select Rule-based and add the rules one by one with the green plus symbol. The rule overview shows the four rules of the first part, each with its filter expression and its colour.

  • Rule 1
    • condition: "REPR2010" > "REPR1990"
    • style: green fill
  • Rule 2
    • condition: "REPR2010" < "REPR1990"
    • style: orange fill
  • Rule 3
    • condition: "REPR2010" = "REPR1990"
    • style: beige fill
  • Rule 4
    • condition: Else
    • style: grey fill

Rule 4 is an Else rule for the features with NULL values, for example the District of Columbia and the territories.

The map after the first part: every state has exactly one fill colour.

Hatching and outlines

Now add three more rules. Each of them only adds something on top of the fill colour.

  • Rule 5
    • condition: "REPR2010" / "POP2010" / mean("REPR2010" / "POP2010") - "REPR1990" / "POP1990" / mean("REPR1990" / "POP1990") > 0
    • style: hatching, without a fill colour

In rule 5, "REPR2010" / "POP2010" calculates the number of seats per inhabitant in 2010. Dividing this value by the mean of the seats-per-inhabitant ratio across all states expresses it relative to the average state. The same calculation is made for 1990. The expression then subtracts the 1990 value from the 2010 value. A result greater than 0 means that the state’s relative representation increased.

  • Rule 6
    • condition: "REPR2010" / "POP2010" = maximum("REPR2010" / "POP2010")
    • style: blue outline, without a fill colour
  • Rule 7
    • condition: "REPR2010" / "POP2010" = minimum("REPR2010" / "POP2010")
    • style: red outline, without a fill colour

Rules 6 and 7 select the states with the most and the fewest seats per inhabitant in 2010.

With every rule we add, we may change the group of features that fall under the Else rule as well. Remember that Else applies to all features that match none of the other rules, also those defined after it. In our case it is hypothetically possible that a state with a NULL value for 1990 turns out to have the most seats per inhabitant in 2010. Because it would then match rule 6, it would lose its grey fill. Therefore it is necessary to replace the existing Else rule by a filter that describes the missing data:

  • Updated rule 4
    • condition: "REPR1990" IS NULL OR "REPR2010" IS NULL
    • style: grey fill

Keep in mind that states that meet several rules receive all the corresponding symbols, drawn on top of each other (see Features that meet several rules). Make sure you sort the rules logically in the rule overview: the fill colours at the top, the hatching and outlines below them, so that they are drawn on top of the fills.

The map after the second part. Every state has a fill colour, and the hatching and outlines lie on top of it.
